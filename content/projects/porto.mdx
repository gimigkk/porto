## The Problem

Most portfolios use the same formula: hero, grid, timeline. They work, but lack identity. I built this to have a distinct point of view and physical feel.

The goal was to build a portfolio site that felt like a physical object. Not skeuomorphic in a cheesy way, but grounded in a real metaphor: **a filing cabinet**.

## Approach

I prototyped the scroll mechanics first. Each major section behaves like a manila folder, stacking as you scroll with tabs peeking from underneath.

This required solving three interconnected problems:

1. **Stacking order**: Each folder slides _under_ the one above using `position: sticky` and calculated top offsets.
2. **Parallax drift**: Folders drift at different rates via Framer Motion's `useTransform` to simulate physical weight.
3. **Custom Scroll**: Integrated [Lenis](https://github.com/darkroomengineering/lenis) for smooth, inertia-based scrolling.

### The Sticky Stack

Each folder section is wrapped in a `position: sticky` container with an increasing `top` value. CSS handles the stacking automatically. Zero JavaScript layout calculations.

```css
/* Each folder gets a progressively larger top offset */
.folder-1 { position: sticky; top: 80px; }
.folder-2 { position: sticky; top: 120px; }
.folder-3 { position: sticky; top: 160px; }
```

The tab at the top of each folder is a simple `border-radius` trick with a pseudo-element that creates the notch effect. It took about 15 iterations to get the geometry right.

### Motion & Feel

Framer Motion drives all the micro-interactions. The parallax effect maps `scrollYProgress` to a subtle Y-axis translation on each folder:

```tsx
const y = useTransform(scrollYProgress, [0, 1], [0, -40]);
```

This creates a parallax effect as you scroll. Each folder shifts independently, reinforcing the layered metaphor.

For the project cards, I went with staggered reveal animations with a spring-based ease curve. Each card enters with a slight upward drift and opacity fade, delayed by `i * 0.15s` based on its grid index.

## The Modal System

Clicking a project card doesn't navigate to a new page. Instead, it appends a `?project=slug` search parameter to the URL and renders a full-screen bottom sheet over the current page.

This was a deliberate architectural choice:

- **Scroll position preserved**: Closing the modal drops you right back where you were.
- **URLs shareable**: The search parameter means every project has a linkable address.
- **Modular architecture**: The `?project=` pattern works on any page without duplicating routing logic.

The modal uses a pure CSS `translateY` animation. I avoided opacity fades and scale transforms to prevent compositing layer explosions and maintain 60fps on lower-end GPUs.

## Typography & Color

The site uses a dark-first palette built on Zinc tones. The three folder sections follow a subtle gradient from `#141416` (About) to `#0e0e10` (Experience) down to `zinc-950` (Projects), giving a sense of depth without any actual shadows.

Each project has an `accent` color used for titles, badges, and hovers. These are passed as inline styles directly from the registry, bypassing dynamic Tailwind classes.

## What I'd Do Differently

If I rebuilt this today, I'd probably skip Framer Motion for the scroll-driven animations entirely and use the native CSS `animation-timeline: scroll()` API. Browser support is finally there, and it would eliminate all the JavaScript overhead for the parallax effects.

I'd also invest more time in the mobile experience. The stacked folder metaphor works beautifully on desktop where you have vertical real estate, but on a phone screen the tabs get cramped. A swipe-based card stack might work better at that breakpoint.
